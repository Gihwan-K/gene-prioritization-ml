# 이 프로젝트가 실제로 무엇을 했는가 — 처음부터

## 0. 먼저, 오해 하나 풀기

> "머신러닝으로 내 분석을 다시 한 거지?"

**아닙니다.** 그게 이 프로젝트의 핵심입니다.

선생님이 하신 것과 제가 한 것은 **문제를 푸는 방식 자체가 다릅니다.**

| | 선생님의 분석 | 이 프로젝트 |
|---|---|---|
| 방식 | **규칙 기반 필터링** | **학습 기반 랭킹** |
| 진행 | 3,305 → 1,893 → 520 → 8개로 좁혀나감 | 3,176개 **전부에 점수**를 매겨 순위를 만듦 |
| 규칙은 누가 정했나 | 사람 (생물학 지식으로) | 데이터에서 학습 |
| 결과의 형태 | 후보 8개 (통과/탈락) | 3,176개의 순위표 (연속적) |
| SYN2-B, CENH3-B는 | **결과** | **정답지** |

비유하자면 — 선생님이 어려운 문제를 손으로 풀어서 답을 냈습니다. 저는 그 답을 **가려놓고** 전혀 다른 방법으로 같은 문제를 푼 뒤, 답을 열어서 맞았는지 확인한 겁니다.

그래서 이 프로젝트가 의미가 있는 겁니다. 같은 방법을 다시 돌렸으면 같은 답이 나오는 게 당연해서 아무것도 증명하지 못합니다. **다른 방법으로 같은 답에 도달했을 때** 비로소 "이 후보들이 방법론에 의존하지 않는 진짜 신호"라는 증거가 됩니다.

그리고 부수적으로, 이 접근법은 **다음 종에 그대로 쓸 수 있습니다.** 선생님의 필터링 규칙은 Aegilops B 염색체에 맞춰 손으로 짠 것이라 밀이나 사탕무에 그대로 옮기기 어렵지만, 랭킹 모델은 데이터만 바꿔 끼우면 됩니다. KWS가 관심 있는 게 정확히 이 부분입니다.

## 1. 왜 이게 "머신러닝 문제"가 되는가

머신러닝은 결국 **"예시를 보고 규칙을 스스로 찾아내는 것"** 입니다. 그러려면 세 가지가 필요합니다.

**① 정답이 있는 예시 (라벨)**
"이건 염색체 분리 유전자다 / 아니다"를 이미 아는 유전자들.

**② 각 유전자를 설명하는 숫자들 (피처)**
발현량, 조직 특이성, 단백질 길이, 아미노산 조성 등. 모델은 유전자 이름을 모릅니다. 오직 숫자만 봅니다.

**③ 답을 모르는 대상**
나머지 유전자들. 여기에 점수를 매기는 게 목적입니다.

### 여기서 막히는 지점 — 그리고 그 해결책

가장 큰 문제는 이겁니다: **양성 예시가 2개(SYN2-B, CENH3-B)뿐이면 학습이 불가능합니다.** 2개로는 어떤 모델도 규칙을 배울 수 없습니다.

그래서 **라벨을 바꿨습니다.**

- 양성으로 쓴 것: "염색체 분리·응집·동원체" GO를 가진 B 유전자 **80개** (Supplementary Table 3, 5에서 추출)
- 음성으로 쓴 것: GO는 있지만 다른 기능인 B 유전자 **2,291개**
- **SYN2-B와 CENH3-B는 양쪽 어디에도 넣지 않고 완전히 뺐습니다**

즉 모델에게 가르친 건 *"어떤 유전자가 염색체 분리 기능을 가질 것 같은가"* 입니다. *"어떤 유전자가 B 제거의 원인인가"* 를 직접 가르친 게 아닙니다. 후자는 애초에 답이 2개뿐이라 가르칠 수가 없습니다.

그리고 나서 물었습니다 — **이렇게 배운 모델이 SYN2-B와 CENH3-B를 상위로 올려놓는가?**

## 2. 데이터가 어떻게 흘러갔는가

```
선생님이 주신 것
├── RSEM 발현량 (40,146 유전자 × 42 샘플)
├── GTF 어노테이션 (유전자 위치·엑손 구조, chrB 표시)
├── TransDecoder 단백질 서열 (30,907개)
├── edgeR DEG 통계 (7 조직 전체)
└── Supplementary Tables (GO, 후보 목록)
                    ↓
        [1단계] 숫자로 된 표 만들기
        3,176개 B 유전자 × 111개 숫자
                    ↓
        [2단계] 정답지 붙이기
        양성 80 / 음성 2,291 / 나머지는 "모름"
        (SYN2-B, CENH3-B는 제외)
                    ↓
        [3단계] 모델 학습 + 교차검증
                    ↓
        [4단계] 3,176개 전부에 점수 매기기
                    ↓
        [5단계] 정답지 열어서 채점
        SYN2-B 상위 3.6%, CENH3-B 상위 1.3%
```

## 3. 111개 "숫자"가 뭔지 — 구체적으로

모델은 유전자를 이렇게 봅니다. `SYN2-B`라는 이름은 모르고, 아래 111개 숫자만 봅니다.

### ① 발현 관련 (약 70개)

RSEM TPM에서 계산했습니다.

| 이름 | 뜻 | SYN2-B 값 |
|---|---|---|
| `ltpm_AR_B` | AR 조직 +B 식물에서의 발현량 (log) | — |
| `tau` | 조직 특이성 지수. 0=모든 조직 균등, 1=한 조직에만 | 0.72 |
| `elim_vs_noelim` | (제거 일어나는 조직) − (안 일어나는 조직) | +1.05 |
| `AR_vs_Root` | AR − 1차뿌리. B가 있는 조직 vs 이미 제거된 조직 | +0.71 |
| `logFC_AR`, `FDR_AR` … | 선생님 edgeR 결과를 조직별로 붙임 | — |

`tau`(조직 특이성)는 이렇게 계산합니다 — 조직별 발현량을 최댓값으로 나눠서 1에서 뺀 뒤 평균냅니다. 한 조직에서만 켜지는 유전자는 1에 가깝고, 어디서나 균등하면 0에 가깝습니다.

### ② 유전자 구조 (7개)

GTF에서 뽑았습니다. 유전자 길이, 엑손 총 길이, 엑손 개수, transcript 개수 등.

### ③ 단백질 성질 (10개)

TransDecoder 단백질 서열에서 계산했습니다. 단백질 길이, 소수성(Kyte-Doolittle), 양전하 비율, 음전하 비율, 방향족 아미노산 비율, 무질서 영역 경향 등.

### ④ 아미노산 조성 (20개)

20종 아미노산 각각의 비율. `aa_V`는 발린이 전체의 몇 %인가.

**이게 놀랍게도 가장 강력한 피처군이었습니다.** 처음엔 노이즈일 거라 의심했는데, 빼고 돌려보니 성능이 절반으로 떨어졌습니다. 단백질의 기능 계열이 아미노산 조성에 실제로 반영되기 때문입니다 — 예를 들어 히스톤은 라이신·아르기닌이 유난히 많습니다.

### ⑤ 유죄추정 피처 2개 (여기가 기술적으로 가장 중요)

**공발현 (guilt-by-association)**: "이미 아는 염색체 분리 유전자들과 발현 패턴이 비슷한가?" 42개 샘플에 걸친 발현 벡터의 상관계수로 계산합니다. *같이 켜지고 꺼지는 유전자는 같은 일을 할 가능성이 높다* 는 원리입니다.

**서열 상동성 (guilt-by-homology)**: "이미 아는 염색체 분리 유전자들과 단백질 서열이 비슷한가?" DIAMOND로 계산합니다.

> **이 두 개는 정답지를 이용해 만든 피처입니다.** 그래서 교차검증 매 fold마다 **그 fold의 학습용 양성만 써서 새로 계산**했습니다. 전체 양성으로 한 번에 계산해두면 정답이 새어 들어갑니다. 흔히 저지르는 실수이고, 이걸 제대로 처리한 게 이 프로젝트에서 가장 신경 쓴 부분입니다.

## 5. 교차검증 — 이 프로젝트에서 제일 중요한 부분

### 교차검증이란

데이터를 5조각으로 나눠서, 4조각으로 배우고 나머지 1조각으로 시험을 봅니다. 이걸 5번 돌려가며 반복합니다. 모델이 답을 외운 게 아니라 **규칙을 배웠는지** 확인하는 방법입니다.

### 그런데 유전체 데이터에는 함정이 있습니다

유전자에는 **파라로그**(중복으로 생긴 거의 똑같은 유전자)가 있습니다.

`Kinesin-A`가 학습 조각에 있고 `Kinesin-B`가 시험 조각에 있으면, 모델은 규칙을 배운 게 아니라 **거의 같은 유전자를 이미 본 것**입니다. 시험 점수가 부풀려집니다. 오픈북 시험인데 그걸 모르는 상태인 거죠.

### 그래서 두 가지 방식으로 나눠봤습니다

```
표준 5-fold        : 무작위로 5조각. 파라로그가 갈라져 들어갈 수 있음
상동성 그룹 5-fold : DIAMOND 그래프로 유전자 패밀리를 먼저 묶고,
                     한 패밀리는 통째로 같은 조각에 넣음
```

결과:

| 피처 구성 | 표준 CV | 그룹 CV |
|---|---|---|
| 발현만 | 0.07 | 0.04 |
| + 유전자 구조 | 0.10 | 0.08 |
| + 단백질 성질 | 0.20 | 0.09 |
| + 아미노산 조성 | 0.33 | **0.16** |
| + 공발현·상동성 | **0.40** | 0.13 |

*(무작위 기준선 = 0.034)*

**두 열의 차이가 곧 파라로그 누출의 크기입니다.** 논문 대부분은 왼쪽 열만 보고합니다.

그리고 마지막 줄을 보세요. 상동성 피처를 넣으면 표준 CV는 0.33 → 0.40으로 오르는데 **그룹 CV는 0.16 → 0.13으로 떨어집니다.** 알려진 유전자의 친척을 찾을 땐 유용하고, 처음 보는 패밀리를 발굴할 땐 오히려 방해가 된다는 뜻입니다.

그래서 최종 결과물을 두 가지 모드로 나눴습니다:

- **Retrieval 모드** (상동성 포함) — "알려진 유전자의 친척을 찾아라". PR-AUC 0.398
- **Discovery 모드** (상동성 제외) — "새로운 패밀리를 발굴하라". PR-AUC 0.168

## 6. PR-AUC가 뭔가

3,176개 중 양성이 80개, 즉 2.5%뿐입니다. 이렇게 한쪽으로 치우친 데이터에서는 **정확도(accuracy)가 무의미합니다** — 전부 "음성"이라고 찍어도 97.5% 정확합니다.

PR-AUC는 "상위 몇 개를 뽑았을 때 그 안에 진짜가 얼마나 있나"를 종합한 값입니다. 무작위로 찍으면 0.034가 나옵니다. 우리 모델은 0.168~0.398이니 **무작위보다 5~12배** 좋습니다.

절대값 0.168은 낮아 보이지만, 이건 "완벽한 분류기"를 만드는 문제가 아니라 **"3,176개 중 먼저 봐야 할 100개를 고르는"** 문제입니다. 그 용도로는 충분합니다. README에 이 한계를 명시해뒀습니다.

## 7. 최종 점수가 어떻게 만들어졌나

```
기능 점수  = ML 모델 출력 (백분위)
발현 점수  = elim_vs_noelim 40% + AR_vs_Root 40% + anther_vs_leaf 10% + tau 10%
             (모두 백분위로 변환 후 가중합, 라벨 사용 안 함)

최종 점수  = 기능 점수 × 발현 점수
```

발현 점수에는 머신러닝이 들어가지 않습니다. 순수하게 생물학 논리로 정한 가중합입니다 — B 제거가 일어나는 조직에서 높고, 안 일어나는 조직에서 낮은 유전자를 우대합니다.

그리고 결과가 이렇게 나왔습니다:

| | 기능 점수 | 발현 점수 | 곱 |
|---|---|---|---|
| SYN2-B | 상위 7.9% | 상위 17.1% | **상위 3.6%** |
| CENH3-B | 상위 11.4% | 상위 2.4% | **상위 1.3%** |

SYN2-B는 기능 쪽이 강하고, CENH3-B는 발현 쪽이 강합니다. **어느 하나만으로는 둘 다 못 잡는데 곱하면 둘 다 잡힙니다.** 이게 이 프로젝트에서 제일 재미있는 결과입니다.

## 8. 결과를 어떻게 읽어야 하나

**신뢰해도 되는 것**

- 상위 20위가 kinesin, NUF2, condensin, SMC, MUS81, Shugoshin으로 채워진 것. GO를 피처로 쓰지 않았는데도 이렇게 나왔습니다
- 1차 뿌리에서만 B 유전자 검출이 급감하는 것. 데이터가 생물학을 스스로 재현했습니다
- 표준 CV와 그룹 CV의 차이. 방법론적으로 견고한 관찰입니다

**조심해야 할 것**

- SYN2-B, CENH3-B 복원은 **n=2**입니다. 우연일 가능성을 배제할 수 없습니다
- 소르굼 보존 후보 3.2배 농축이 통계적으로는 더 의미 있는 신호인데, 값 자체는 크지 않습니다
- 라벨이 GO 기반이라 **어노테이션이 잘 된 유전자가 유리합니다.** "not classified" 유전자는 구조적으로 불리합니다

## 9. 이 환경에서 못 한 것 = IPK에서 할 수 있는 것

제가 작업한 클라우드 환경은 외부 네트워크가 막혀 있어 두 가지를 포기했습니다.

| 포기한 것 | 왜 좋은가 | IPK에서 가능? |
|---|---|---|
