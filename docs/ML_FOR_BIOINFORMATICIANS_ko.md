# 바이오인포매틱스 하던 사람을 위한 머신러닝 설명

## 0. 먼저, 살짝 바로잡기

> "공통적으로 연산되는 분석 파이프라인을 만든 다음에 아무 지노타입을 넣어도 결과가 나오게 하는 거잖아?"

**반은 맞는데, 그게 머신러닝의 정의는 아닙니다.**

왜냐하면 — 선생님의 `fastp → STAR → RSEM → edgeR` 파이프라인도 **이미 그렇습니다.** 아무 genotype의 fastq를 넣어도 DEG 표가 나옵니다. 재사용 가능한 파이프라인이라는 건 두 방식의 공통점이지 차이점이 아닙니다.

진짜 차이는 여기입니다:

> **선생님의 파이프라인에서는 모든 규칙을 사람이 씁니다.
> 머신러닝에서는 규칙을 데이터에서 찾아냅니다.**

구체적으로 — 선생님은 이렇게 정하셨습니다.

```r
up_genes <- deg %>% filter(FDR < 0.01, logFC > 1)
```

`0.01`과 `1`은 **선생님이 고른 숫자**입니다. 생물학적 판단으로요. 이게 규칙 기반입니다.

저는 이런 걸 하나도 쓰지 않았습니다. 대신 "이 80개는 염색체 분리 유전자고, 이 2,291개는 아니다"라는 **예시만** 주고, 111개 숫자 중 무엇을 어떤 값에서 잘라야 그 둘이 가장 잘 나뉘는지 **알고리즘이 스스로 찾게** 했습니다.

## 1. 사실 선생님은 이미 모델을 학습시켜 보셨습니다

본인 R 코드를 다시 보세요.

```r
dge  <- estimateDisp(dge, design)
fit  <- glmFit(dge, design)        # ← 여기가 "학습"입니다
lrt  <- glmLRT(fit, coef = 2)      # ← 여기가 "사용"입니다
```

`glmFit`은 **음이항 일반화선형모형(negative binomial GLM)을 데이터에 적합시키는** 함수입니다. 이게 바로 모델 학습입니다. `fit`이라는 객체 안에는 데이터에서 추정된 계수들이 들어 있습니다. 그리고 `glmLRT`가 그 적합된 모델을 가져다 씁니다.

scikit-learn도 정확히 같은 구조입니다.

```python
model.fit(X, y)              # glmFit 에 해당
model.predict_proba(X_new)   # glmLRT 에 해당
```

**이름만 다르지 하는 일은 같은 계열입니다.** 그러니 완전히 새로운 세계에 들어가는 게 아니라, 이미 쓰고 계시던 것의 사촌을 배우는 겁니다.

### 그럼 뭐가 다른가 — 세 가지

| | edgeR (통계적 추론) | 머신러닝 (예측) |
|---|---|---|
| **목적** | "이 유전자가 유의하게 다른가?" → p값 | "이 유전자의 점수는 얼마인가?" → 순위 |
| **모형 형태** | 사람이 지정 (`~ group` 설계행렬) | 알고리즘이 유연하게 결정 |
| **검증** | 필요 없음 (가설검정이므로) | **필수** — 안 하면 외운 걸 실력으로 착각 |

세 번째가 핵심입니다. edgeR은 "이 데이터에서 차이가 있나"를 묻기 때문에 학습/시험 분리가 필요 없습니다. 머신러닝은 "**처음 보는** 유전자에도 통하나"를 묻기 때문에, 데이터를 쪼개서 시험을 봐야 합니다. 안 그러면 답을 외운 모델이 만점을 받습니다.

교차검증이 필요했던 이유가 이겁니다. 그리고 파라로그 누출을 걱정했던 것도 — 시험 문제가 학습 문제와 거의 같으면 오픈북 시험이 되니까요.

## 2. "학습된 모델"이 물리적으로 뭔가

추상적으로 느껴지실 텐데, **선생님 데이터로 실제 학습된 모델을 열어봤습니다.**

```
트리 개수 : 400
1번 트리의 노드 수 : 29
```

400개의 작은 결정트리입니다. 1번 트리의 실제 내용:

```
if hom_max_pos <= 53.350:
   if aa_V <= 0.054:
      if aa_M <= 0.026:
         if aa_T <= 0.037:  →  점수 -0.1120
         else:              →  점수 +0.4828
      else:                 →  점수 -0.1158
   else:
      if mean_ltpm <= 0.267:
         if cv_Anther_B <= 1.111: → 점수 +0.4215
         else:                    → 점수 -0.1101
      ...
else:
   →  점수 +0.1060
```

**이게 전부입니다.** if-else 문 더미입니다.

중요한 건 — `53.350`, `0.054`, `0.026` 이런 숫자를 **제가 정하지 않았습니다.** 알고리즘이 2,371개 유전자를 보면서 "어디서 자르면 양성과 음성이 가장 잘 나뉘나"를 전부 시도해보고 고른 값입니다. 이게 "학습"의 실체입니다.

트리 하나는 성능이 형편없습니다. 그래서 **400개를 순차적으로 쌓습니다** — 1번 트리가 틀린 것을 2번 트리가 보정하고, 그 둘이 틀린 것을 3번이 보정하는 식으로요. 최종 점수는 400개 점수의 합입니다. 이게 gradient boosting입니다.

### 좀 더 읽기 쉬운 버전

같은 데이터로 트리 **하나만** 깊이 3으로 학습시키면 이렇게 나옵니다. 생물학적으로 읽힙니다.

```
알려진 분리 유전자와 서열이 안 비슷하다 (hom_max_pos ≤ 53)
├─ 조직 특이성이 낮다 (tau ≤ 0.29)
│  └─ 제거 조직 편향이 약하다  →  양성일 확률 66%
├─ 조직 특이성이 높다 (tau > 0.29)
│  ├─ 단백질이 짧다 (≤ 792 aa)  →  음성 (77%)
│  └─ 단백질이 길다 (> 792 aa)  →  양성 (71%)
알려진 분리 유전자와 서열이 비슷하다 (hom_max_pos > 53)
└─ 양전하 아미노산이 많다 (frac_pos > 0.18)  →  양성 (99%)
```

마지막 줄을 보세요 — **양전하(K, R) 비율이 높으면 거의 확실히 양성**입니다. 히스톤과 DNA 결합 단백질의 특징이죠. 모델이 생물학을 배운 게 아니라 숫자에서 패턴을 찾은 건데, 결과적으로 생물학적으로 말이 되는 규칙에 도달했습니다.

## 3. 두 번째 질문 — "보통 소프트웨어 써서 하는 거야?"

**아닙니다. 여기서 감각이 제일 많이 다릅니다.**

선생님이 쓰시던 도구들은 **독립 실행 프로그램**입니다.

```bash
STAR --runMode alignReads --genomeDir idx --readFilesIn r1.fq r2.fq
rsem-calculate-expression --bam ...
```

파일을 넣으면 파일이 나옵니다. `module load STAR` 하고 명령어를 칩니다.

**머신러닝에는 그런 게 없습니다.** scikit-learn은 프로그램이 아니라 **라이브러리**입니다. `sklearn --input x --output y` 같은 건 존재하지 않습니다.

```bash
sklearn --train data.csv     # ← 이런 명령어는 없습니다
```

대신 파이썬 스크립트 안에서 `import`해서 씁니다. R에서 `library(edgeR)` 하는 것과 완전히 같은 방식입니다. edgeR도 실행파일이 아니라 R 패키지잖아요 — 그거랑 똑같습니다.

**즉, 이 프로젝트에서 "소프트웨어"는 제가 쓴 스크립트 8개 그 자체입니다.**

그래서 저장소가 `run_star.sh`, `run_rsem.sh` 같은 셸 파이프라인이 아니라 `.py` 파일 묶음인 겁니다.

### 딱 하나 예외

DIAMOND는 선생님이 아는 방식의 도구입니다. 실행파일이고, conda로 설치하고, 명령줄에서 부릅니다. 그래서 `slurm/01_diamond.sbatch`만 선생님한테 익숙한 모양이고, 나머지는 파이썬입니다.

### 핵심 ML 코드는 몇 줄인가

놀라실 텐데, **10줄입니다.**

```python
from sklearn.ensemble import HistGradientBoostingClassifier
from sklearn.model_selection import StratifiedKFold
from sklearn.metrics import average_precision_score

model = HistGradientBoostingClassifier(class_weight='balanced')

for train_idx, test_idx in StratifiedKFold(5, shuffle=True).split(X, y):
    model.fit(X.iloc[train_idx], y[train_idx])          # 학습
    pred = model.predict_proba(X.iloc[test_idx])[:, 1]  # 예측
    print(average_precision_score(y[test_idx], pred))   # 채점
```

나머지 코드 전부(제 스크립트의 95%)는 **머신러닝이 아니라 데이터 가공**입니다. RSEM 결과를 표로 만들고, GTF를 파싱하고, GO를 추출하고, 피처를 계산하는 것. 선생님이 이미 매일 하시는 그 일입니다.

**머신러닝 프로젝트의 실제 노동량 배분이 대략 이렇습니다:**

```
데이터 준비·피처 만들기   ████████████████████  80%
검증 설계 제대로 하기      ████                  15%
모델 학습                 █                      5%
```

그래서 **선생님이 불리하지 않습니다.** 80%는 이미 하실 줄 아는 일이고, 그 80%를 잘하는 사람이 좋은 모델을 만듭니다. 모델 부분은 라이브러리가 다 해줍니다.

## 4. 선생님 워크플로 ↔ 머신러닝 워크플로

| 하는 일 | 선생님 방식 | 머신러닝 |
|---|---|---|
| 환경 구성 | `module load` / conda·mamba | **conda·mamba (동일)** |
| 실행 방식 | 셸에서 실행파일 호출 | **파이썬 스크립트 실행** |
| 클러스터 | `srun`, `sbatch` | **동일** |
| 병렬화 | `--runThreadN 50` | `n_jobs=-1` 또는 fold를 병렬로 |
| 입력 | fastq, bam | **표 (유전자 × 숫자)** |
| 출력 | count 표, DEG 표 | **점수·순위 표 + 학습된 모델 파일** |
| 그림 | R ggplot2 | matplotlib (또는 결과를 R로 넘겨도 됨) |
| 결과 검증 | 생물학적 타당성, 실험 검증 | **교차검증 + 생물학적 타당성** |

바뀌는 건 사실상 **"실행파일 호출" → "파이썬 스크립트"** 하나입니다. 나머지 인프라는 그대로입니다.

### SLURM에서는 구체적으로 뭐가 다른가

거의 안 다릅니다. 비교해보면:

```bash
# 선생님이 하시던 것
srun --cpus-per-task=50 --mem=100G --pty bash
module load STAR
STAR --runThreadN 50 --genomeDir ...

# 머신러닝
srun --cpus-per-task=8 --mem=32G --pty bash
conda activate geneprio
python src/04_model_v2.py
```

**자원 요구가 오히려 훨씬 작습니다.** STAR 매핑은 50코어에 100GB가 필요하지만, 이 모델 학습은 8코어에 32GB면 넉넉합니다. 데이터가 40,146 × 111 표 하나라 메모리에 통째로 들어갑니다.

주의할 점 하나만:

```bash
export OMP_NUM_THREADS=1
```

sbatch 스크립트에 이걸 넣어뒀습니다. numpy가 내부적으로 스레드를 마구 만들어서 SLURM이 할당한 CPU 수를 초과하는 걸 막는 장치입니다. 안 넣으면 클러스터 관리자한테 메일 받습니다.

**진짜로 자원이 필요해지는 건 ESM-2 단백질 언어모델뿐**입니다. 그건 GPU가 필요하고, `slurm/03_esm2_embeddings.sbatch`에 준비해뒀습니다.

## 5. STAR 인덱스로 이해하기

`fit`과 `predict`가 헷갈리시면 이 비유가 잘 맞습니다.

| STAR | 머신러닝 |
|---|---|
| `--runMode genomeGenerate` — 게놈에서 인덱스 생성. 오래 걸림. 한 번만 | `model.fit(X, y)` — 데이터에서 모델 생성 |
| 인덱스 디렉터리가 디스크에 남음 | 모델 객체가 남음 (`joblib.dump`로 파일 저장 가능) |
| `--runMode alignReads` — 인덱스로 새 read 처리. 빠름 | `model.predict()` — 새 유전자에 점수 부여. 빠름 |

한 번 만들어두면 재사용한다는 점이 같습니다. 다만 인덱스는 게놈에서 **결정론적으로** 나오는 반면, 모델은 **정답 예시가 있어야** 만들어진다는 게 차이입니다.

## 6. 친구한테 물어볼 때 쓸 용어

머신러닝 전공 친구들이 있다고 하셨으니, 대화가 통하는 단어로 정리해드립니다.

| 용어 | 이 프로젝트에서 | 친구한테 이렇게 말하면 됨 |
|---|---|---|
| **feature** | 111개 숫자 | "피처 111개, 표 형태 데이터" |
| **label / target** | 양성 80 / 음성 2,291 | "이진 분류, 양성 비율 3.4%" |
| **class imbalance** | 양성이 3.4%뿐 | "불균형 심해서 PR-AUC로 평가했어" |
| **cross-validation** | 5-fold | "5-fold CV" |
| **data leakage** | 파라로그 누출 | "그룹 누출 있어서 GroupKFold 썼어" |
| **gradient boosting** | 400개 트리 | "HistGradientBoosting, sklearn 내장" |
| **feature importance** | SHAP | "SHAP으로 기여도 봤어" |
| **ablation study** | 피처군별 성능 비교 | "피처 그룹 ablation 했어" |
| **inference** | 3,176개에 점수 부여 | "전체에 스코어링" |

친구한테 한 문장으로 설명한다면:

> "피처 111개짜리 이진 분류인데 양성이 3.4%밖에 안 돼서 PR-AUC로 평가했고, 도메인 특성상 그룹 누출이 있어서 GroupKFold로 보수적 검증도 같이 돌렸어."

이렇게 말하면 바로 알아듣고, 아마 "오 제대로 했네"라고 할 겁니다. 그룹 누출까지 신경 쓰는 건 흔치 않거든요.
